Project

Data Lake & Analytics

A serverless analytics pattern: an S3 raw zone, crawled by AWS Glue into a Data Catalog, queried with serverless SQL by Amazon Athena, and visualized with Amazon QuickSight.

This AWS architecture is fully designed and documented below, but intentionally not deployed — QuickSight's per-seat licensing (~$9–24/user/month) and ongoing Glue job costs aren't justified for a portfolio demo, so the query demo below runs entirely on a small, static, baked-in dataset with zero AWS calls.

Architecture

How it works (as designed, not as deployed)

This diagram shows the architecture exactly as documented in this project's cdk/lib/data-lake-analytics-stack.ts and README — since nothing here is actually running, the steps below describe what the real pipeline would do rather than something you can trigger.

S3 (raw zone)
1
Glue Crawler + Catalog
2
Athena (serverless SQL)
3
QuickSight
  1. 1

    Source data lands in the S3 raw zone

    The raw zone is the single source of truth every downstream service reads from — nothing is transformed or deleted in place.

  2. 2

    A Glue crawler updates the Data Catalog

    The crawler inspects the raw zone's objects and keeps a Glue database/table schema up to date, so every query engine downstream shares one schema definition.

  3. 3

    Athena runs serverless SQL against the catalog

    A Lambda-fronted API would call start_query_execution against a dedicated workgroup, then poll for results — no cluster to provision, pay only per query.

  4. 4

    QuickSight visualizes the results

    QuickSight reads directly from Athena's result set — it's account-level and per-seat licensed rather than something the CDK stack provisions itself.

Use cases

Where this pattern fits

A serverless data lake shows up anywhere raw, semi-structured data needs to become queryable without standing up and managing a database or a data warehouse cluster.

Ad-hoc business reporting

Answering a one-off question against raw event or transaction logs without waiting on a data engineering ticket to build a pipeline first.

Log & clickstream analytics

Landing application or clickstream logs straight in S3 and querying them with SQL instead of standing up a dedicated log analytics platform.

Executive dashboards

Feeding QuickSight (or any BI tool that can read Athena results) from a single, consistently cataloged source of truth across teams.

Pricing

What this would actually cost

Nothing here is deployed, so nothing here is billing today — these are estimates based on public AWS list pricing for what the architecture above would cost if it were running.

Light volume

~$15/mo

A handful of ad-hoc queries a day against a small dataset — Athena's per-TB-scanned pricing is nearly free at this scale, so QuickSight's flat per-seat fee dominates the bill.

Light Moderate Regular Heavy Multi-seat

Query and dashboard volume

What drives the cost

  • Amazon QuickSight — the dominant cost at small scale: ~$9–24 per author/reader seat per month, billed whether or not anyone opens a dashboard that day.
  • Amazon Athena — billed per TB of data scanned per query (~$5/TB); effectively free at a demo's data volume.
  • AWS Glue — crawler runs and Data Catalog storage are billed per DPU-hour and per object; small but non-zero if the crawler runs on a schedule.
  • S3, Lambda & API Gateway — storage and per-request pricing; effectively free at this scale.

Design decisions

Why I designed it this way

A few choices here aren't the only way to build this — here's the reasoning behind them.

Athena over a provisioned query engine

Redshift or EMR would both work here, but both bill for provisioned capacity whether or not a query is running. Athena's per-query pricing matches this project's actual usage pattern — occasional, ad-hoc — far better.

QuickSight left out of the CDK stack

QuickSight is an account-level subscription with its own per-seat billing rather than a stack-scoped resource — trying to provision it per-project via CDK wouldn't reflect how it's actually adopted in a real organization, so the stack stops at Athena and documents QuickSight as the next layer instead.

A static demo dataset, not a live query interface

A real SQL-input box over a live Athena connection would cost real money per keystroke from anonymous visitors with no guardrails. Three preset "queries" over a small baked-in dataset show the same request/wait/results shape without that exposure.
